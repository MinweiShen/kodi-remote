# iPhone 浏览器 Kodi 遥控器

日期：2026-10-27（北京时间）
状态：已于 2026-10-27 部署到 Pi，真实 Kodi/uinput 联调通过；16 项 Python 测试、2 项 Node 测试及浏览器检查通过。iPhone 触感和电视字形仍待用户手动确认。运行和验收步骤见根目录 TESTING.md。

## 已确认的需求

- 只针对 Kodi 优化，iPhone 在家庭局域网中通过浏览器访问 Pi。
- 核心操作：鼠标、中文文字输入、播放器快捷键。
- 原触控板的问题是移动倍率太低，手指划很远而光标只移动一点；用户未报告延迟问题。
- 支持前进和后退 10 秒、1 分钟、10 分钟。
- 菜单中提供播放控制、字幕开关、字幕轨道、音轨、上一集和下一集等按钮。
- 手机显示当前片名、时间和进度；支持拖动进度条，松手后才跳转。
- 主界面仅包含紧凑的 Kodi 信息、播放进度条和尽可能大的触控板；没有播放项目时隐藏进度条，并将空间还给触控板。
- 所有操作按钮通过菜单打开，菜单覆盖在触控板上，使用更大的按钮方便点按；菜单入口并入顶部信息栏。
- 以 Pi 上的本地视频为主要使用与验收场景。
- 上一集和下一集根据当前视频所在文件夹寻找，不要求用户预先建立播放队列。

以下交互细节和技术选型是本提案的推荐默认值，可在实机体验后调整。

## 方案

使用一个原生 systemd 服务提供网页和 WebSocket。保留 uinput 负责鼠标，将播放和文字操作交给 Kodi JSON-RPC。手机只连接该服务，由服务连接本机 Kodi。

```mermaid
flowchart LR
  Phone[iPhone Safari] -->|局域网 HTTP / WebSocket| Remote[Pi 遥控服务]
  Remote -->|鼠标位移、按键、滚轮| Uinput[/dev/uinput]
  Uinput --> Kodi[Kodi]
  Remote <-->|文字、导航、播放指令、状态| RPC[Kodi JSON-RPC]
  RPC <--> Kodi
```

不依赖 X11/Wayland 或桌面串流。根据已有项目记录，Kodi 运行于 GBM/DRM 会话，现有 remote-touchpad 已采用 uinput；该情况仍需重新连接实机确认。

## 手机界面

主界面以触控板面积优先。顶部保留紧凑的 Kodi 信息栏，菜单入口并入信息栏右侧；其下仅在有播放项目时显示进度条，剩余可用区域全部作为触控板。主界面不常驻播放、导航或输入按钮。

```text
┌───────────────────────────────┐
│ Kodi · 已连接             ☰   │
│ 当前片名（单行）              │
│ 00:24:15 ━━━━━●━━━━━ 01:42:00 │
├───────────────────────────────┤
│                               │
│          大触控板             │
│                               │
│                               │
│                               │
│                               │
│                               │
│                               │
│                               │
│                               │
└───────────────────────────────┘
```

- 信息栏中的长片名省略显示，完整片名可在菜单中查看，不让多行标题挤占触控板。
- 暂停仍视为存在播放项目，进度条保留；停止或播放结束且没有活动项目时完全隐藏片名和进度区，不保留占位。状态未知或断线时显示紧凑提示，不展示可操作的陈旧进度条。
- 页面使用当前可见视口高度，适配 Safari 工具栏和安全区域；主界面尽量不滚动，不设置固定比例的空白区或底部工具栏。

### 覆盖式操作菜单

点击顶部菜单入口后，在触控板区域内显示覆盖面板；不推挤页面、不缩小触控板布局，也不覆盖顶部 Kodi 信息和进度。面板打开时，下面的触控板暂停接收输入。

菜单按“播放 / 导航 / 输入 / 设置”分组，推荐记住上次打开的分组：

| 分组 | 内容 |
| --- | --- |
| 播放 | 播放/暂停、停止、六个定长跳转按钮、音量、静音、字幕开关与轨道、音轨、上一集/下一集 |
| 导航 | 大尺寸方向键与确认、返回、主页、上下文菜单 |
| 输入 | 中文文字框、“发送并确认”及输入目标提示 |
| 设置 | 灵敏度、速度加速、拖拽锁定及连接信息 |

- 定长跳转用两列三行布局，左列后退、右列前进，每个按钮明确标出 10 秒、1 分钟或 10 分钟。
- 常用操作按钮目标高度 56–64 CSS px，触控区域不小于 44 CSS px，按钮间留出间距；内容多时只让覆盖面板内部滚动，不缩小按钮挤入一屏。
- 面板有明确的关闭入口。连续跳转、音量调整、字幕和音轨操作后保持菜单打开，便于连续点按；关闭后立即恢复完整触控板。
- 开菜单时结束当前触控手势并释放已按下的鼠标键。覆盖层隔离点击、滚动和触摸事件，防止穿透成鼠标移动或点击。
- 关闭菜单的那次触摸不传给触控板；等待下一次独立落指才开始移动。播放状态变化造成进度区出现/消失时，也不得因布局变化制造光标位移。
- 输入框聚焦、键盘弹出时只调整菜单内部布局。Kodi 请求文字时在信息栏提示；用户点击菜单中的输入框后聚焦，避免依赖 iOS 自动弹出键盘。
- 不向手机传输视频。片名与播放状态足够支持遥控，用户看电视完成选片。

## 鼠标手感

采用相对触控板：抬手重新落下后可以继续移动，不把手指坐标映射成屏幕绝对坐标。

- 单指移动；轻点左键；双指轻点右键；双指滑动滚轮。
- 拖拽使用明确的“拖拽锁定”开关，避免初版用长按手势引入误触；退出页面、取消手势、连接断开或会话超时均释放按键。
- 速度使用手指 CSS 像素位移 / 时间估计，平滑处理后计算连续变化的加速倍率；不按每个事件的位移大小决定加速，避免采样频率改变手感。
- 初始候选：基础倍率 3，设置可调 1–8；速度加速从 1 倍平滑上升至最多 3 倍，可关闭。具体数值待实机调校，不是已验证参数。
- 在服务端应用位移变换；保留小数余量，避免细小移动取整后丢失。前端只采样和打包，避免重复加速。
- 位移按帧合并，正常情况下最多约 60 次/秒；合并时保留总位移和必要的速度样本。点击前先提交此前位移，不跨越按键事件合并。
- 仅触控板区域禁止页面滚动和系统手势干扰；其他面板保持正常网页交互。
- 灵敏度和加速偏好保存在当前浏览器；服务端为当前连接使用对应配置。

验收目标：在实际电视分辨率下，快划一次触控板的主要宽度可以从屏幕一侧移动到另一侧；慢划仍可停在相邻菜单项上。首次使用用“太慢 / 合适 / 太快”调整倍率，最终手感需用户用 iPhone 实测。

## 播放与跳转

六个明确的相对跳转按钮：−10、+10、−60、+60、−600、+600 秒，直接提交对应秒数，不借用 Kodi 方向键的可变跳转步长。

- 单击执行一次；初版不长按连发，尤其避免 10 分钟按钮长按误跳。
- 串行执行跳转请求；每个动作绑定播放项目的当前代次，切片或换集后丢弃旧项目的未执行动作。
- 断线不重放，超时不自动重试相对跳转、播放切换或上下集等非幂等操作；先重新读取状态，避免执行两次。
- 进度条拖动期间只更新预览时间，不让后台进度覆盖手指位置；松手发送一次绝对时间跳转。
- 无播放项目时主界面隐藏进度条，菜单中的播放相关控件显示不可用状态；时长未知或内容不支持 seek 时禁用跳转控件，并解释原因。
- 以 Kodi 返回的实际位置为准，接受视频关键帧带来的定位偏差；边界行为需实测，界面时间不显示负数或超过总长。
- 上一集/下一集根据当前文件夹识别；具体规则如下，不要求 Kodi 当前已有播放队列。
- 音量控制 Kodi 软件音量；音频直通导致软件调音不可用时显示原因，不假装改变电视/功放音量。

### 按文件夹寻找上下集

1. 从 Kodi 获取正在播放的视频路径，由服务端确定父目录，通过本机文件系统只枚举这一层的可播放视频文件。排除目录、字幕、临时下载文件和可识别的预告、样片、OP/ED 等附加内容，并拒绝指向目录外的符号链接。实机证实 Kodi 的目录枚举接口会拒绝未注册为媒体源的目录，因此本地视频枚举由服务端完成。
2. 优先识别 `S01E02`、`第02集`、`E02`、`EP02` 等明确的季/集标记；对 `[02]`、` - 02` 等较弱格式，要求候选文件具有一致的剧名和命名结构，不把年份、分辨率或编码数字当集号。
3. 对可唯一识别的同一剧集、同一季，寻找集号减一或加一的文件。例如当前 `S01E09`，下一集选择 `S01E10`。缺集时显示“下一集未找到”，不悄悄跳过缺失集。
4. 单纯数字命名且文件夹内结构一致时按自然数字顺序识别，例如 `1.mkv → 2.mkv → 10.mkv` 的排序；跳转仍遵守缺集提示规则。
5. 同一集有多个版本、剧名混杂、合集跨多集或集号无法可靠解析时，显示按自然顺序排列的候选文件，让用户选择；不随意播放排序上的邻项。
6. 默认不跨文件夹或跨季，不从第一集/最后一集循环回另一端。无前后集时给出清楚的不可用状态。
7. 点击后先验证目标仍存在且当前播放项目未改变，再调用 Kodi 打开该文件。候选选择使用服务端生成的条目标识，浏览器不提交任意文件路径。失败时保留当前播放，不先发送停止命令。
8. 仅手动切集；本设计不添加播完自动连播，也不改动 Kodi 现有的连播设置。

以上解析策略是实现默认值，需用用户真实文件名联调；识别不确定时允许选择候选是功能的一部分。

## 中文输入

手机端使用普通文字框和 iOS 输入法。仅在用户点击“发送并确认”时提交完整 Unicode 文本；输入法选字过程中不发送未完成的拼音。

- 用户先在电视上打开 Kodi 搜索或输入框，再在手机编辑并发送。
- 以标准 Kodi 文字对话框为第一版支持范围；具体皮肤的内嵌筛选框及插件自定义控件需要单独验证。
- 使用 Kodi 请求输入的通知提示当前输入目标；重连后已有输入框的识别能力需实测。目标不明时提示用户重新打开输入框，不盲发到任意焦点。
- 确认发送成功后反馈；失败或断线时保留手机草稿，供用户手动重发。
- 整段提交是编辑后的完整内容，不逐字模拟键盘。已有文本的替换行为必须在实际 Kodi 对话框测试；不承诺所有控件行为一致。
- 中文显示还依赖电视端 Kodi 皮肤字体包含中文字形，联调时检查。

## 状态与连接

- 页面显示“连接中 / 可控制 / Kodi 不可用 / 已断线”，区分遥控服务在线与 Kodi 在线。
- 优先通过 Kodi 通知刷新播放状态；辅以低频校准。播放时手机按时间戳推进显示，暂停时冻结；不以高频轮询驱动鼠标。
- 获取当前活动播放器，不硬编码 player id。Kodi 重启后重新发现并恢复状态。
- 手机锁屏或进入后台后停止发送动作；回到前台重新连接并拉取完整状态，不补发旧操作。
- 控制命令与状态读取独立调度，不让慢的状态请求阻塞鼠标或按键释放。
- 初版单个活动控制会话；另一设备打开时显示占用状态，用户主动接管后释放旧会话所有按键。

## 服务与访问

- 原生服务，由普通用户运行，仅授予 uinput 所需设备权限，沿用现有 systemd 加固配置作为起点。
- 前端资源全部随服务提供；家庭网络断开外网时仍能使用。
- 推荐手机继续使用 Pi 的固定局域网地址；正式端口在联调后确认。新旧服务并行验收期间不争用同一监听端口。
- 局域网 HTTP 与随机访问密钥，适用于当前可信家庭网络。密钥输入后换取会话，不写入项目文件、访问日志或前端资源；WebSocket 建连同样校验会话及 Origin。
- 手机只看到白名单遥控操作，不提供任意 JSON-RPC、任意 shell 或任意文件访问能力。
- 后端优先通过回环接口连接 Kodi；其监听和鉴权配置需实机核实，不能为了遥控而无认证暴露 Kodi 管理接口到整个网络。
- 验收通过后再切换常用入口，保留旧 remote-touchpad 可恢复的程序和配置；本次设计阶段不变更远程服务。

## Kodi 接口依据

官方 JSON-RPC 文档确认了所需能力，实际部署必须使用目标 Kodi 的版本与接口自省结果校验：

| 功能 | 接口 |
| --- | --- |
| 当前播放器、片名、状态 | `Player.GetActivePlayers`、`Player.GetItem`、`Player.GetProperties` |
| 定长/进度条跳转 | `Player.Seek`：`value.seconds` / `value.time` |
| 中文整段输入 | `Input.SendText`；`done=true` 确认并关闭打开的输入对话框 |
| 请求输入通知 | `Input.OnInputRequested` |
| 播放与停止 | `Player.PlayPause`、`Player.Stop` |
| 文件夹上下集 | 服务端枚举当前视频父目录，识别目标后通过 `Player.Open` 播放 |
| 字幕和音轨 | `Player.SetSubtitle`、`Player.SetAudioStream` |
| 音量和静音 | `Application.SetVolume`、`Application.SetMute` |
| 导航 | `Input` 中对应的方向、确认、返回、主页操作 |

来源：[Kodi 官方 JSON-RPC API 文档](https://kodi.wiki/view/JSON-RPC_API/v13)。这些是文档能力，不是已在用户 Pi 验证的结果。

## 实机核实与验收

初版设计时 Pi 离线；2026-10-27 晚间已通过 SSH 完成部署和真实 Kodi/uinput 检查，结果见 TESTING.md。以下是完整验收标准，其中 iPhone 触感和电视实际字形仍由用户确认：

1. 重新读取 `/home/pi/README.md` 与 `/home/pi/README-PROXY.md`；检查 Kodi 版本、运行方式、现有输入服务和可用 JSON-RPC 传输。遵守现有代理配置，不修改 v2rayA 核心配置或启用旧 v2ray.service。
2. 在电视上测试普通慢划、快速跨屏、点击、滚动、拖拽与断线释放；用实际 iPhone Safari 校准倍率。
3. 用至少一段长于 20 分钟的本地视频验证六个跳转按钮、连续点击、视频开头/结尾、暂停中跳转及拖动松手跳转；对比 Kodi 实际位置。
4. 在实际使用的搜索对话框输入“流浪地球 2”，验证中文、空格、数字、已有内容替换、取消、断线重连和重复发送行为。
5. 用含多音轨/字幕的视频验证覆盖菜单；用实际番剧文件夹测试 `E09 → E10`、纯数字命名、缺集、重复版本、临时下载文件及不同季；无需建立播放队列。无字幕、无其他音轨、无前后集时状态正确。
6. 检查实际音频输出是否直通；确认软件音量可用性与界面反馈一致。
7. 验证 Safari 锁屏恢复、Wi-Fi 中断、Kodi 重启、两设备接管后均无幽灵点击、重复跳转或卡住的按键。
8. 在 iPhone Safari 验证未播放时进度区完全隐藏、暂停时保留、停止后空间归还触控板；检查主界面只有信息、条件显示的进度条和触控板。菜单不推挤布局，大按钮容易点按，菜单内滚动和关闭均不向 Kodi 发送误触。验证 Safari 工具栏变化、横竖屏切换和中文键盘弹出时布局可用。

设计完成的依据是以上用户确认与公开接口核对；功能完成的依据是实现后通过这些实机验收。
